# Try the two workflows

[Watch the 2:20 English-captioned demo](https://www.youtube.com/watch?v=n2h0D3Z27H8)
or try the steps below. No account or API key is needed. All names and events in
the sample pack are fictional.

Download [the small sample pack](examples/judge-demo.zip?raw=true), unzip it,
and keep its four JSON files handy. The [plain JSON files](examples/) are also
available for inspection. These are sample histories, not imported user data.

Use **two separate browsers**, or a normal window and a private window, for
independent local storage. Two ordinary tabs in the same browser share the
same saved records. Keep private windows open during the exercise.

The links below select the sample's `judge-sample-v1` workspace. Start with empty
copies. If you already ran the exercise, repeat imports intentionally add zero;
use fresh temporary browser sessions for the initial-count demonstration.

## Reception: five events, four attendees

1. Open [reception](https://tokuitao.github.io/deadair-kit-kiroween-2026/apps/reception/?workspace=judge-sample-v1)
   in both clients while connected. In client A choose **Read JSON file** and
   select `reception-desk-a.json`; review the preview and **Import records**.
   A shows **3** attendees. On client B import `reception-desk-b.json`; B shows **2**.
2. On A choose **Create handoff QR**, then **Download this QR PNG**. On B choose
   **Read QR image** and select that generated image. The preview says **3 new
   records**; choose **Import records**.
3. B now shows **4 attendees**, with **5 records** in its history. Both desks
   independently checked Sam in, so Sam counts once while both events remain.
4. Read the same QR on B again. The preview says **0 new records**. Importing it
   keeps the count at **4**, and the history at **5**.

The JSON files only seed each independent desk. The actual handoff in steps 2–4
is the QR PNG generated by the working app.

## Lending: preserve a conflict, carry a resolution

1. Open [equipment lending](https://tokuitao.github.io/deadair-kit-kiroween-2026/apps/lending/?workspace=judge-sample-v1)
   in both clients. Import `lending-desk-a.json` on A and `lending-desk-b.json`
   on B using **Read JSON file**, review, and **Import records**.
2. A shows `DRILL-01` with **Alex**; B shows the same item with **Sam**.
   Each copy initially knows one loan. Make and download A's handoff QR, then
   read and import that PNG on B.
3. B shows **2 active loans** and **Overlapping loans need a decision**.
   Both borrowers remain visible. Use **Return** on the row **With Alex**.
   B now shows **1 active loan**, with **Sam**, and retains **3 history records**.
4. Make a new handoff QR on B. Read and import its PNG on A. A's preview adds
   **2 new records**. Both copies now show Sam's active loan and all three events.

This resolves the selected record after the operator checks reality. It cannot
prevent a double loan while the two desks are disconnected.

## Why these are two apps from one skeleton

| Application | Distinct state and completed task |
| --- | --- |
| `apps/reception/` | Check-in events become a unique attendee count and a retained arrival trail. Repeated attendance is not another person. |
| `apps/lending/` | Loan/return events become active borrowers and overlapping loans. A return references one selected loan, preserving the evidence. |

Both reuse event-ID union, app/workspace isolation, import preview, QR collection,
camera lifecycle, local storage and offline assets. See [the starter guide](STARTER.md)
to adapt the foundation, and [the Kiro workflow](KIRO-WORKFLOW.md) for actual AI
development contributions and counterexamples.

## Offline and evidence boundaries

Initially load each app while connected. Then work and reload offline in the
same browser session. The public video demonstrates independent browser origins
on one Mac and actual QR image exchange. Camera scanning is implemented and has
synthetic-stream checks; physical phone/camera validation remains pending.

Records stay in browser storage. Closing a private session discards that
session's records. QR and JSON exports contain actual record contents. Prototype
handoffs are not encrypted or peer-authenticated. Use the fictional sample pack.
