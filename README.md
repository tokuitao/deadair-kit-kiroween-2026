# DeadAir Kit

Two small field apps that keep records locally and exchange them through QR images or JSON files. Built as a new Kiroween 2026 project.

[Open the working prototype](https://tokuitao.github.io/deadair-kit-kiroween-2026/) · [Reception](https://tokuitao.github.io/deadair-kit-kiroween-2026/apps/reception/) · [Equipment lending](https://tokuitao.github.io/deadair-kit-kiroween-2026/apps/lending/)

- **Reception:** check attendees in, search the desk list, and retain repeated check-ins in an audit trail while counting each attendee once.
- **Equipment lending:** record loans and returns, then display overlapping loans after disconnected devices exchange their histories.

The apps share an immutable event-union engine and transport validation. They have separate source folders in `apps/reception` and `apps/lending`.

## Run locally

Requires Node.js 24 or newer.

```sh
npm ci
npm test
npm run build
npm run preview
```

Open `http://localhost:5127`. To try an independent browser storage area on the same computer, open `http://127.0.0.1:5127` as well. These are two browser origins, not a substitute for real device testing.

## Try a real handoff

1. Load an app on each device while connected. Use the same workspace name in both.
2. Create a record on the first device. Select **Create handoff QR**, then **Download QR PNG**.
3. On the other device, select **Read QR image**, choose the PNG, review the preview, and select **Import records**.
4. Import the same image again: no duplicate records should be added.
5. For lending, record a loan for the same item independently on each device. Handoff displays both active loans as an overlap. Return the selected loan to resolve it, then carry the updated history back.

QR images contain the actual records, including names, rather than a URL. Treat exported images and JSON files as copies of those records. This prototype does not authenticate peers or encrypt handoffs.

## Offline behavior and limits

- The service worker precaches the app assets after an initial connected load. Wait for the first load to finish before disconnecting.
- Local records use browser storage. Clearing browser data removes them; export a JSON backup first.
- Independent disconnected devices cannot prevent two people from borrowing the same item. The app retains both loans and shows the overlap after handoff.
- Live camera scanning starts only with an explicit button and decodes locally with no microphone or frame uploads. Image-file QR decoding and JSON import remain available. Camera access needs HTTPS or localhost and a supported device/browser.
- Camera lifecycle behavior is covered by simulated-media tests. Browser checks using a synthetic canvas MediaStream also exercised actual video playback, Japanese QR decoding, preview/confirmation and the permission-denial fallback. Physical camera and phone validation are still pending; do not treat these checks as hardware validation.
- A QR handoff is limited to 1,600 UTF-8 bytes; use JSON for larger histories. JSON imports are limited to 500 KB and 1,000 operations.
- All history is exchanged in this first version. Incremental peer acknowledgements and large-history QR sequences are future work.
- Record data stays in the browser. There is no runtime AI service, account system, or data backend.

## How Kiro was used

Kiro CLI 2.37.1, using its `auto` model, generated the first shared engine, its tests, and `.kiro/steering/project.md`. Independent review found two counterexamples not covered by the original tests: mixed namespaces within one import batch and attendee-name selection that depended on input order. Kiro then applied focused engine fixes and added four regression cases. The final tests were executed independently.

Codex handled orchestration, the application interfaces, lending projection, QR transport, packaging, and independent browser verification. Kiro usage is recorded accurately; this version does not claim that Kiro hooks, MCP integrations, or every source file were used/generated by Kiro. These workflows will be added only when exercised.

For the camera increment, Codex wrote requirements in `.kiro/specs/camera-handoff/` before implementation. Kiro read them, wrote the design/tasks, generated the first scanner and five synthetic-media tests, and partially wired the UI. A service throttling error ended that run. Codex then fixed independently identified restart/playback/error cleanup issues, completed both interfaces, and added four regression tests. This is CLI specification-guided development; it does not claim an IDE spec workflow.

## Tests

The domain tests cover event-union properties, namespace isolation, ID collisions, duplicate attendance, deterministic name selection, double loans, out-of-order returns, transport validation, and QR byte limits. Test success does not establish real-world adoption or competition placement.
